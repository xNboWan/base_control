# Saber 串口带宽与波特率配置说明

本文说明 Saber 数据输出频率与串口带宽的关系、当前 STM32F427 的串口速率限制，以及 STM32 与 Saber 同步修改波特率的流程。

本文依据 2026-09-29 的项目配置编写。代码片段用于指导实现。

## 1. 当前项目配置与选择建议

当前配置如下：

| 项目 | 当前配置 |
|---|---|
| MCU | STM32F427IIH6 |
| Saber 通信串口 | USART6 |
| USART6 波特率 | 115200 |
| 串口格式 | 8N1：8 位数据、无校验、1 位停止位 |
| 硬件流控 | 无 |
| USART6 过采样 | 16 倍 |
| USART6 外设时钟 | PCLK2 = 90 MHz |
| Saber 输出频率 | `saberInit()` 中设置为 100 Hz |
| 数据包配置 | 卡尔曼加速度、卡尔曼角速度、欧拉角 |
| 接收 DMA 缓冲区 | `dma_buf[256]` |
| IMU 读取任务周期 | 10 ms |

配置来源：[串口初始化](../Core/Src/usart.c)、[时钟配置](../Core/Src/main.c)、[CubeMX 配置](../base_control.ioc)、[Saber 驱动](../User/Devices/Src/saber.c)、[IMU 任务](../User/Modules/Src/imu.c)。

对于当前数据包：

- 100 Hz 使用 115200，带宽有余量。
- 200 Hz 建议使用 230400。
- 400～500 Hz 建议使用 460800。
- 800～1000 Hz 建议使用 921600；超过 400 Hz 还需要 Saber 的 Swift 模式。

只修改 STM32 的串口波特率，Saber 不会自动跟随。两端必须配置相同的波特率、数据位、停止位和校验方式。

## 2. 数据帧与带宽计算

### 2.1 当前完整帧为 57 字节

当前配置的数据项及长度如下：

| 内容 | 字节数 |
|---|---:|
| 外层帧头、地址、CID、MID、Payload 长度 | 6 |
| 加速度：2 字节 PID + 1 字节长度 + 12 字节数据 | 15 |
| 角速度：2 字节 PID + 1 字节长度 + 12 字节数据 | 15 |
| 欧拉角：2 字节 PID + 1 字节长度 + 16 字节数据 | 19 |
| BCC 与帧尾 | 2 |
| **完整帧** | **57** |

欧拉角数据中的 16 字节包含 roll、pitch、yaw 和 4 字节保留字段。具体字节位置与数值见[惯导回传数据帧解析示例](惯导回传数据帧解析示例.md)。

### 2.2 8N1 每字节占用 10 个线路位

```text
1 位起始位 + 8 位数据 + 1 位停止位 = 10 位/字节

串口数据量（字节/秒） = 完整帧字节数 × 每秒帧数
需要的线路带宽（bit/s） = 完整帧字节数 × 每秒帧数 × 10
```

这里的帧长度包含协议头、BCC 和帧尾。对于普通二进制 UART，波特率的数值对应每秒传输的线路位数。

| 输出频率 | 串口数据量（字节/秒） | 需要的线路带宽（bit/s） | 建议波特率 | 建议档位下的线路占用 |
|---:|---:|---:|---:|---:|
| 50 Hz | 2,850 | 28,500 | 57600 | 49.5% |
| 100 Hz | 5,700 | 57,000 | 115200 | 49.5% |
| 200 Hz | 11,400 | 114,000 | 230400 | 49.5% |
| 400 Hz | 22,800 | 228,000 | 460800 | 49.5% |
| 500 Hz | 28,500 | 285,000 | 460800 | 61.8% |
| 800 Hz | 45,600 | 456,000 | 921600 | 49.5% |
| 1000 Hz | 57,000 | 570,000 | 921600 | 61.8% |

表中的建议波特率预留了余量，并不是每档输出频率唯一可用的波特率。

例如，200 Hz 使用 115200 时，线路占用为：

```text
114000 / 115200 ≈ 98.96%
```

理论上能容纳这些连续数据，但余量很小，因此建议提高到 230400。增加回传数据项或改变串口格式后，需要重新计算。

Saber 的 Sophisticate 模式支持 0、50、100、200、400 Hz；Swift 模式还支持 500、800、1000 Hz。0 Hz 表示关闭输出。参见[协议文档](<软件架构和 API 协议.pdf>) §5.40，第 80～81 页。

## 3. STM32F4 串口波特率的限制

### 3.1 上限取决于具体芯片与外设时钟

不能把整个 STM32F4 系列的串口上限视为同一个数值。当前项目使用 STM32F427，USART6 的时钟来自 APB2。

本项目时钟关系为：

```text
HSE = 12 MHz
SYSCLK / HCLK = 180 MHz
PCLK1 = 45 MHz
PCLK2 = 90 MHz
USART6 使用 PCLK2 = 90 MHz
```

USART6 的速率上限按过采样倍数计算：

| 过采样配置 | 上限关系 | PCLK2 = 90 MHz 时的上限 |
|---|---|---:|
| 16 倍 | PCLK2 / 16 | 5.625 Mbaud |
| 8 倍 | PCLK2 / 8 | 11.25 Mbaud |

这与 [ST 官方数据手册 DS9405，§3.24、Table 8](https://www.st.com/resource/en/datasheet/stm32f427ii.pdf#page=38) 一致。90 MHz 的 PCLK2 需要满足芯片的 Over-drive 条件；本项目时钟初始化启用了 Over-drive。相关限制见 [DS9405，Table 17](https://www.st.com/resource/en/datasheet/stm32f427ii.pdf#page=95)。

因此，当前配置使用 921600 或 1500000 都在硬件速率上限以内，可以继续保留 `UART_OVERSAMPLING_16`。

### 3.2 实际波特率有分频误差

UART 通过外设时钟分频产生波特率，某些目标值不能被精确生成。按照本项目标称的 90 MHz PCLK2、16 倍过采样计算：

| 设置的波特率 | BRR | 实际波特率，约 | 分频误差，约 |
|---:|---:|---:|---:|
| 230400 | `0x0187` | 230179 | −0.096% |
| 460800 | `0x00C3` | 461538 | +0.160% |
| 921600 | `0x0062` | 918367 | −0.351% |
| 1500000 | `0x003C` | 1500000 | 0% |

这些是标称时钟下的分频结果，实际通信还受到两端时钟误差和线路质量影响。分频与接收容差的说明见 [ST 官方参考手册 RM0090](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405415xx-stm32f407417xx-stm32f427437xx-and-stm32f429439xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。

## 4. Saber 的波特率编码与配置参数

### 4.1 波特率字段发送的是编码

Saber 的 `SetComPortParam` Payload 使用 1 字节表示波特率档位：

| 波特率 | 配置编码 |
|---:|---:|
| 9600 | `0x01` |
| 38400 | `0x02` |
| 57600 | `0x03` |
| 115200 | `0x04` |
| 230400 | `0x05` |
| 460800 | `0x06` |
| 921600 | `0x07` |
| 1500000 | `0x08` |

因此，设置 Saber 为 921600 时发送 `0x07`；设置 STM32 时使用数值 `921600`。

### 4.2 串口配置 Payload 共 5 字节

```text
params[0]：波特率编码
params[1]：字长
params[2]：停止位
params[3]：奇偶校验
params[4]：流控
```

手册 §5.48 的示例把字长写为 `0x01`，但参数说明和 §6.6.1 又要求字长为 8，存在不一致。为了保持当前有效的 8N1 配置，推荐先读回设备的 5 字节串口参数，只修改 `params[0]`，保留后 4 个字段。

相关定义见[协议文档](<软件架构和 API 协议.pdf>) §5.48～5.50、第 87～91 页，以及 §6.6、第 140～143 页。

## 5. 双端同步修改波特率的流程

### 5.1 涉及的命令

| 操作 | 请求 CID | 请求 MID | 请求 Payload 长度 | 响应 MID |
|---|---:|---:|---:|---:|
| GetComPortParam：读当前参数 | `0x05` | `0x02` | 0 | `0x82`，Payload 为 5 字节 |
| SetComPortParam：设置新参数 | `0x05` | `0x01` | 5 | `0x81` |
| SetComPortParamHandshake：确认新串口 | `0x05` | `0x10` | 0 | `0x90` |

响应还要通过外层帧校验，并检查 CID 中的错误码为成功。

**必须使用旧波特率发送设置命令，再使用新波特率发送握手命令。设置命令发送后，需要在 3 秒内完成新波特率握手，否则设备会恢复原波特率。** 这是 §6.6.1 与 §6.6.5 规定的流程。

### 5.2 示例：115200 切换到 921600

1. STM32 与 Saber 都以 115200 通信，进入 CONFIG 模式。此时尚未启动数据接收 DMA。
2. 发送 `GetComPortParam`，确认收到成功的 `0x82` 响应。该响应 Payload 为 5 字节，普通帧总长为 13 字节。将 Payload 复制到 `params[5]`。
3. 保持后 4 个参数，只设置 `params[0] = 0x07`。
4. 使用旧波特率 115200 发送 `SetComPortParam`，确认命令已经发送完成。
5. 立即把 STM32 的 USART6 设置为 921600。
6. 使用新波特率发送 `SetComPortParamHandshake`，接收并检查 `MID=0x90` 的成功响应。需要重试时，整个过程仍必须受 3 秒窗口约束。
7. 握手成功后，双方继续使用 921600。完成数据包和更新率配置，再进入 MEASURE 模式并启动 DMA。

下面只展示发送与本地切换的关键调用顺序。`params` 的前提是已经由有效的读参数响应填充；握手 ACK 的接收、总超时和失败恢复需要由配置接口处理。

```c
// Saber 已进入 CONFIG 模式，接收 DMA 尚未启动
// params[5] 已保存 GetComPortParam 返回的配置
params[0] = 0x07;  // Saber：921600 的编码

// 仍使用旧波特率发送设置命令
saberSendFrame(saber,
               CLASS_ID_COMMUNICATION_CONFIG,
               CMD_ID_SET_COMPORT_PARAM,
               params, 5);

// STM32 切换到新波特率
saber->huart->Init.BaudRate = 921600;
if (HAL_UART_Init(saber->huart) != HAL_OK)
    return false;

// 使用新波特率发送握手命令
saberSendFrame(saber,
               CLASS_ID_COMMUNICATION_CONFIG,
               CMD_ID_COMPORT_PARAM_HANDSHAKE,
               NULL, 0);

// 下一步：在整体3秒窗口内读取、校验握手ACK，必要时短间隔重试
```

不能只收到 `SetComPortParam` 的响应，就认为 STM32 和 Saber 已经成功切换。最终判据应是新波特率下的握手成功响应。

未收到握手 ACK 时，也不能直接认定 Saber 已经回到旧速率：如果握手请求已被设备处理而 ACK 丢失，双方可能处于不同状态。恢复时可以先在新波特率读回配置；没有响应时，在回退窗口结束后再尝试旧波特率。

### 5.3 现有发送与超时接口需要配合

当前 `saberSendFrame()` 返回 `void`，没有向调用者传出 `HAL_UART_Transmit()` 的结果。实现波特率切换接口时，建议让发送接口返回成功状态，发送失败时及时处理。

当前 `saberAckCheck()` 调用 `saberRecvFrame()`，而后者会重复使用传入的超时时间进行阻塞接收。因此，一个 `timeout` 值不能严格限制整个过程的总耗时。

用于波特率握手时，应从设置命令发送开始记录统一的截止时间；每次接收或重试只使用剩余时间。寻找帧头时也要检查截止时间，避免持续收到无效字节后一直等待。这样才能满足设备的 3 秒握手要求。

## 6. 在 saberInit 中接入，以及掉电保存

推荐在驱动初始化期间完成切换，调用顺序可以整理为：

```text
以设备当前波特率初始化 STM32 USART6
    → 完成唤醒处理，进入 CONFIG
    → 读回串口参数
    → 修改 Saber 参数、切换 STM32、完成新波特率握手
    → 配置数据包和输出频率
    → 按需保存配置到 Flash
    → 进入 MEASURE
    → 启动接收 DMA
```

接收 DMA 启动后，不能继续把当前阻塞接收式 `saberAckCheck()` 与 DMA 接收混用。运行过程中需要重新配置时，应让 ACK 经由统一的 DMA 接收入口处理，或者先协调停止接收，完成配置后重置解析状态并重新启动。

如果希望新配置掉电后保留，可以发送 `ConfigurationWriteToFlash`：`CID=0x01、MID=0x08、Payload 长度为 0`，并检查 `MID=0x88` 的成功响应。该命令将用户配置保存到 Flash，见协议 §6.2.9～6.2.10。

设备保存为 921600 后，STM32 下一次启动也应以 921600 初始化。可以在 CubeMX 的 USART6 参数中设置启动波特率，使重新生成的配置与设备一致。初次切换前，仍要先用设备原来的波特率通信，不能提前改成新值后再发旧速率配置命令。

## 7. 提高频率后，还需要检查 DMA 缓冲区

提高波特率解决的是线路传输能力；接收任务仍需要在 DMA 覆盖未读字节之前完成消费。

当前 IMU 任务每 10 ms 调用一次读取接口，在这个时间内产生的数据量为：

| 输出频率 | 10 ms 内平均产生的字节数 |
|---:|---:|
| 100 Hz | 57 |
| 200 Hz | 114 |
| 1000 Hz | 570 |

因此，1000 Hz 下继续使用 `dma_buf[256]` 和 10 ms 轮询，会覆盖未读数据。可以扩大原始 DMA 缓冲区，或者利用接收事件通知任务更及时地消费。

缓冲区应按照**最长无法处理接收数据的时间**来估算，包含任务等待、被其他任务抢占和解析耗时：

```text
缓冲区容量 > 每秒接收字节数 × 最长处理间隔 + 余量
```

例如，1000 Hz、57 字节帧、10 ms 处理间隔产生约 570 字节，1024 字节可作为初步选择；若实际处理间隔更长，还需要继续增加容量或提高处理及时性。

DMA 原始缓冲区用于保存字节流，组帧缓存用于拼接完整协议帧，两者的容量可以分别设计。环形 DMA 的读位置相等也可能意味着数据已经被覆盖一整圈，不能仅凭这个条件证明没有丢数据。

其他任务仍通过 `imuRead()` 获取最新状态。DMA 字节消费和组帧由一个接收任务负责；一次解析到多帧时，只发布最后一个有效样本，符合当前“只需要最新状态”的使用方式。
